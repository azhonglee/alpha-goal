# 执行边界

当涉及子代理、归属不清、多路径工作、生成输出、跨仓库 / worktree / 子模块工作或无关用户变更时，使用本参考。

## 子代理委托

只委托有边界且独立的工作。

提供：

- 任务 ID；
- 范围和工作目录；
- 归属边界；
- 已批准契约 / 计划证据；
- 约束和非目标；
- 预期证据；
- 回执结构。

回执标签：

- `DONE`
- `DONE_WITH_CONCERNS`
- `NEEDS_CONTEXT`
- `BLOCKED`

只有检查文件、归属、证据和关注点后，才接受委托输出。委托永远不能绕过目标契约、迭代记录、验证结论、最强风险证据或最终检查。

## 归属边界

编辑前识别：

- 仓库根目录和当前分支；
- 当前目录是否为关联 worktree；
- 脏状态和无关用户变更；
- 每个被触达路径所属的 git 根目录；
- 嵌套 `.git` 目录和子模块；
- 本地规则文件，例如 `AGENTS.md`、`AGENTS.override.md`、`CLAUDE.md` 或 `code_review.md`。

除非目标契约或用户批准，否则不要修改仓库、worktree、子模块、生成输出负责人或流程边界。

## 生成产物

涉及生成文件时：

- 识别生成器源和生成目标；
- 可行时修改源，而不是只修改生成输出；
- 必要时运行或记录生成命令；
- 避免会重写无关表面的局部重新生成；
- 在迭代记录中记录生成产物。

## 用户变更与无关变更

如果存在无关用户变更：

- 不覆盖它们；
- 避免大范围格式化；
- 使用定向编辑；
- 说明如何保留它们；
- stash、revert、移动或清理前先询问。
