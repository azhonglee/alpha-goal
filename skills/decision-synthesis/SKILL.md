# 决策综合

问题属于复杂系统，而不是单纯实现任务时，使用本技能。它在 `goal-contract`、`system-model` 或 `control-loop` 继续前，先综合目标和决策边界。

## 使用时机

请求包含以下情况时使用：

- 多个利益相关方且目标冲突；
- 成功标准难以量化、偏好主要是定性的，或存在战略取舍；
- 高不确定性、数据不完整或环境变化；
- 涉及宽范围架构、迁移、组织工作流、安全、合规、研究或产品策略；
- 多个子系统相互作用，优化一部分可能让另一部分失稳；
- 需要结合专家判断、经验性证据、模型和场景分析。

对验收清楚且证据直接的局部低风险任务，不使用本技能。

## 边界

- 不改实现文件，不部署，不 push，不修复数据，也不宣称最终完成。
- 不虚构利益相关方偏好或用户自有风险决策。
- 不把综合结果当成实现授权。变更前，必须通过 `goal-contract` 把选定方向转成目标契约。
- 区分事实、专家判断、假设、待证假设、场景和决策。
- 如果已有闭环台账，综合前从 `.alpha-goal/YYYYMMDD-<slug>/control-state.md` 读取 `最新控制路由`。只更新综合相关状态：目标冲突、用户自有决策、场景假设和推荐路由。

## 流程

```text
判定复杂度 -> 收集视角 -> 构建综合图 -> 运行综合轮次 -> 解决决策 -> 产出综合记录 -> 路由
```

### 1. 判定复杂度

分类问题：

- `simple`: 目标已知、路径已知、证据直接；路由出去。
- `complicated`: 部件很多，但目标稳定且可分解；使用 `system-model` 或 `goal-contract`。
- `complex`: 存在反馈、自适应、模糊性或目标冲突；继续综合。
- `complex-giant-like`: 子系统多、含人类决策、可观测性弱、风险高，且不存在单一完整模型；使用完整综合和显式人工决策闸门。

### 2. 收集视角

对每个相关视角记录：

- 目标或关切；
- 证据、模型或专业判断依据；
- 不确定性和假设；
- 与其他视角的冲突；
- 决策负责人；
- 可能改变决策的证据。

视角可包括用户、客户、运营、安全、法务 / 合规、工程、数据、UX、研究、可维护性、成本、交付和长期策略。

### 3. 构建综合图

创建定性 / 定量综合图：

```text
综合图:
- 系统目的:
- 候选目标:
- 约束:
- 利益相关方与决策负责人:
- 子系统与交互:
- 关键状态变量:
- 可用证据与置信度:
- 缺失证据:
- 冲突 / 取舍:
- 场景:
- 稳定性风险:
- 候选控制策略:
```

有定量证据时优先纳入，但不要制造虚假精确度。定性判断必须标注，并关联到负责人或来源。

### 4. 运行综合轮次

对 `complex`、`complex-giant-like` 或任何视角冲突场景，在解决决策前运行一轮或多轮 `综合轮次`。结构见 `references/synthesis-round.md`。对开放复杂巨系统工作，使用 `references/meta-synthesis-hall.md` 定义的综合研判工作台，保存角色、假设、模型、异议和收敛条件。

每轮必须连接：

- 人类或专家判断及其决策负责人；
- 机器证据、模型输出、测试、日志、指标或探针；
- 综合研判工作台状态：多种假设、模型或利益相关方视角仍未收敛时的状态；
- 冲突、矛盾或缺失传感器；
- 任何能把定性判断转成有界证据的指标或代理；
- 应成为验收证据或传感器证据的指标转译候选；
- 能降低不确定性的用户自有决策或下一待证假设。

当最小下一动作清楚时停止：目标契约候选、系统建模问题、用户决策、阻塞项或有界验证假设。

### 5. 解决决策

识别：

- 智能体可以建议的决策；
- 用户必须作出的决策；
- 需要显式接受的风险；
- 能稳定工作的非目标；
- 最小可行下一契约；
- 不可逆行动前所需证据。

如果利益相关方冲突无法解决，返回决策请求，而不是静默选择。

### 6. 产出综合记录

默认把完整决策综合记录写到 `.alpha-goal/YYYYMMDD-<slug>/decision-synthesis.md`，并更新闭环台账的产物登记。TUI 默认展示紧凑 Markdown 表格 `综合摘要`。只有用户要求、文件持久化受阻，或用户自有决策需要复核完整取舍时，才在聊天中打印完整记录。

紧凑记录字段:

```text
- 核心张力:
- 综合研判工作台:

- 用户自有决策:
- 非目标:
- 所需证据:
- 指标转译:
- 路由:
```

### 7. 路由

- 当稳定推荐方向和指标转译可以形成目标契约时，路由到 `goal-contract`。
- 当子系统边界或反馈信号仍不清楚时，路由到 `system-model`。
- 当需要用户自有决策、风险接受、预算 / 时间取舍或利益相关方优先级时，路由到用户。
- 只有综合未授权变更，且下一动作只是比较既有证据包和拟声明时，才路由到 `evidence-verify`。
- 只有已有有效目标契约，且综合只是收窄下一切片、没有改变授权时，才路由到 `control-loop`。
